01 · Commitments

Ten decisions everything else hangs on

  1. C1

    Workflows are TypeScript programs

    The graph is the call graph: await, parallel, if, while. No separate graph DSL.

  2. C2

    Every step returns a schema-validated value

    schema required on agent, human.*, check, workflow I/O. No free-text channel.

  3. C3

    Durable by journaled replay

    Every side effect — agent, human, bash, fetch, fs — is a journaled step; resume re-executes code and serves completed steps.

  4. C4

    Replay is edit-tolerant, never fatal

    Seq fast path → content-addressed salvage → live. Reordering is free; rewording re-runs. --reuse key for iteration. A miss re-runs; it never lies.

  5. C5

    Humans are steps

    ctx.human.* suspends durably; answers validated like any output.

  6. C6

    The journal owns the diffs

    Write steps → worktree → patch → enforced scope → journaled merge.

  7. C7

    Providers, not a host

    Claude Agent SDK + Codex SDK behind one AgentProvider; per-step provider/model/effort.

  8. C8

    Real accounting

    Tokens/USD from SDK usage; hard ceilings; pool shared with children.

  9. C9

    Two records, both generated

    Mechanical journal + semantic report (checks, ledger, risk) as projections.

  10. C10

    Engine is a library; hosts are thin

    CLI · MCP server (callable from Claude Code and Codex) · daemon.

03 · Authoring

TypeScript in, typed values out

defineWorkflow(meta, run); everything comes through ctx (no ambient globals), so the schema you pass in types the value you get back.

import { defineWorkflow, z } from "@weft/sdk";
import { Finding, Verdict, FixResult } from "./schemas";        // relative imports: bundled + hashed with the script

export default defineWorkflow({                                   // name derives from the filename
  description: "Find bugs, verify across vendors, fix with approval",
  input:  z.object({ paths: z.array(z.string()) }),
  output: z.object({ fixed: z.array(Finding), skipped: z.array(Finding) }),
}, async (ctx, { paths }) => {
  ctx.phase("Find");
  const found = ctx.ok(await ctx.parallel(paths.map(p =>
    ctx.agent(`Find correctness bugs in ${p}. Cite file:line.`,
      { schema: z.object({ findings: z.array(Finding) }), key: `find:${p}`, effort: "high" }))));   // C2
  const findings = found.flatMap(r => r.findings);                   // typed; no nulls

  ctx.phase("Verify");
  const real = ctx.ok(await ctx.pipeline(findings)
    .step(f => ctx.parallel((["claude", "codex", "claude"] as const).map((provider, i) =>
      ctx.agent(`Try to refute: ${f.claim} (${f.file}:${f.line})`,
        { schema: Verdict, provider, key: `refute:${f.file}:${f.line}:${i}` }))))      // C7
    .filter(votes => ctx.ok(votes).filter(v => v.real).length >= 2)
    .map((_votes, f) => f)
    .run());

  ctx.phase("Fix");
  const go = await ctx.gate({ action: `Apply fixes for ${real.length} bugs`, risk: "medium" });   // C5 — policy: auto or ask
  if (!go.approved) return { fixed: [], skipped: real };
  const fixes = ctx.ok(await ctx.parallel(real.map(f =>
    ctx.agent.detailed(`Fix and add a focused test: ${f.claim}`, {
      schema: FixResult, isolation: "worktree",
      write: { paths: [f.file, "**/*.test.ts"], also: ["pnpm-lock.yaml"], mode: "warn" },   // C6
      key: `fix:${f.file}` }))));
  await ctx.integrate(fixes, { order: "sequential", onConflict: "ask" });   // explicit patches, journaled merge

  ctx.phase("Check");
  await ctx.check("tests", { exec: ["pnpm", "test"], required: true });
  return { fixed: real, skipped: [] };
});

  • Module mode: .weft/workflows/*.ts + relative imports (./schemas, ./lib), esbuild-bundled into one script, content-hash versioned, callable by name. Inline mode: a session hands the engine a TS string (MCP/CLI); same gate; persisted under the run.

Relative imports are allowed (bundled, hashed). Missing schema is a TypeScript error. Runs in a worker_thread with a replaced global (determinism fence, not a security boundary), with source maps so errors point at .ts lines; structuredClone(result) → "did you forget to await…?".

Side effects from workflow code

const { paths } = await ctx.fs.glob("src/**/*.ts");                                        // journaled
const tests  = await ctx.exec("pnpm", ["test", "--reporter=json"], { schema: TestReport, timeout: "10m" });   // no shell
const issues = await ctx.fetch("https://api.github.com/repos/o/r/issues?state=open",
  { headers: { Authorization: ctx.secret("GITHUB_TOKEN") }, schema: z.array(Issue) });          // secret resolved engine-side, redacted in journal
if (tests.failed.length > 0) await ctx.exec("git", ["stash"], { risk: "medium" });                 // risk → gate → policy

Each call is a step: keyed by its arguments, executed by the engine, result journaled, served on replay (the workflow observes what it observed then — the Temporal activity rule). A second fs.read of the same path after an agent edited it is a new occurrence, so it re-reads. Workflow code does not write files through ctx.fs; edits come from agents as patches. fetch hosts, exec risk, and per-provider rate limits are engine policy.

Tiers are fixed per op; a workflow may raise a tier, never lower it — the run's approvalPolicy decides what "ask" means, with patterns (push: { "origin/main": "ask", "origin/wip/*": "auto" }). Write ops are idempotency-checked on resume: if the journaled sha/ref exists, the step is served; otherwise it re-executes and the run is marked diverged. isolation (§10) is built on the same package.

04 · Structured outputs

The only way out of a step is a validated object

  • Decisions are enums (verdict, severity, needs_human); code branches on them (SGR: decisions as types).
  • Evidence travels with claims; integrate rejects outputs without it.
  • Registry lints for portability (deep unions, recursion) and auto-falls back to the terminating tool.
  • Non-agent steps are structured too: exec/bash → {exitCode, stdout, stderr}, fetch → {status, body}; pass schema to parse JSON into a typed value.
  • Any schema shape: primitives are wrapped as { value } on the wire and unwrapped; Zod is default, Valibot/ArkType via Standard Schema. An agent at maxTurns without a final call gets one forced "finalize" turn before failing.

06 · Journal & replay

Resume is re-execution with the answers already known

Replay algorithm (C3, C4)

  1. Index completed steps bySeq and byHash (hash → FIFO of unconsumed entries); note completion order.
  2. Run the code fresh. Each step: identity = explicit key, else H(kind, prompt|payload, opts, schema) + occurrence; seq = ++n.
  3. Fast path: bySeq[seq].hash === hash → serve. Cached completions are delivered in journaled completion order, so continuations and seq numbers reproduce.
  4. Salvage: else byHash[hash] unconsumed → serve, append replay.salvaged. Survives inserted/removed/reordered steps (native stops at the first edit). It does not survive rewording a prompt — that step and its dependants re-run. --reuse key (dev mode) matches on identity only, accepting deliberate staleness for fast iteration.
  5. Live: else append replay.diverged once, execute; orphaned entries stay for audit, never served.
  6. Cached write steps re-apply their patch only if the tree hash differs from the journaled post-merge hash. Unanswered human steps re-surface, never duplicate.

12 · Persistence

One journal, pluggable stores, generated projections

interface JournalStore {
  append(runId, events[]): Promise<void>;               // atomic batch · monotonic seq
  read(runId, fromSeq?): AsyncIterable<Event>;  watch(runId): AsyncIterable<Event>;
  list(filter?): Promise<RunSummary[]>;  snapshot(runId, projection): Promise<void>;   // speeds indexing, never replaces replay
}
interface BlobStore { put(bytes, meta): Promise<BlobRef>; get(ref): Promise<Uint8Array> }

.weft/runs/<id>/
  journal.jsonl      ← truth
  script.ts          ← what ran (inline mode) / def hash (module mode)
  blobs/<hash>       ← patches · transcripts · large outputs
  state.json         ← projection: FSM, steps, scopes, checks
  report.md          ← projection: outcome · changes · checks · ledger · risk · next step
  tree.json          ← projection: live tree for UIs
  • Stores: fs is the store (one portable run dir per run). An optional node:sqlite index over all local runs makes ls/search fast for the daemon and UI; it is derived from the journals and can be deleted and rebuilt.
  • Projections are rebuilt from events; the journal keeps output hashes + blob refs so indexing stays fast.

16 · Build order

Four milestones, each independently useful

  1. M1

    Core loop + resume

    sdk · core · gate · store-fs · provider-mock · provider-claude; ctx.fs/bash/fetch side-effect steps; ctx.git read ops; required schemas via terminating tool; validation + repair; journal; seq-fast-path resume; CLI. Exit: §03 runs end to end on Claude and resumes after a kill.

  2. M2

    Humans, budget, Codex, salvage

    durable human.* with CLI + MCP; approval policy (incl. ctx.git write ops by risk tier); budget pool; provider-codex; content salvage + replay --dry; ctx.workflow; local daemon + web UI v1 (runs list, live tree, answer requests). Exit: cross-vendor verify; a run suspended on approval is answered from the web UI and resumes from a new process.

  3. M3

    Patches, checks, report

    worktrees, patch capture, scope enforcement, integrate with conflict → human; check/decide/claim; state.json + report.md; stdlib; testing; web UI: report, explain, output diff. Exit: resume on a fresh clone rebuilds the tree from the journal.

  4. M4

    Index, signals, observability

    index-sqlite over all local runs; signal/sleep wake-ups via the daemon; OTel spans; UI polish. Exit: hundreds of local runs list and search instantly; a local CI script signals a waiting run over localhost.

17 · Risks

What could bite, and the current answer

  • Sandbox ≠ security boundary. Scripts are our own agents'. If untrusted scripts ever enter: isolated-vm or subprocess; the seam exists.
  • Codex scope is post-hoc. Always-worktree + quarantine keeps the integration tree clean. Revisit if the SDK exposes a per-tool hook.
  • Native structured-output limits (deep unions). Registry lints; terminating tool is the universal baseline.
  • Replay ordering after divergence. Live and cached interleave; salvage absorbs; worst case a cache miss. replay --dry makes regressions visible.
  • Journal growth. Replay is code-only (fast); snapshots + blob offload keep indexing small; compaction of orphaned events later.
  • Model nondeterminism is not a problem: a cached output is a valid past answer; nothing assumes steps reproduce.
  • Temporal instead? The journal model stays compatible with a Temporal-backed store as an optional package later, but a self-contained fs journal is what makes Weft a standalone CLI you can run in any checkout.
